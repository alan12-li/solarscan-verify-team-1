Problem slice

The hard cases: HVAC, skylights, shadows, obstructions

The problem: the scanner is right until it isn't

Con Edison's existing rooftop solar scanner handles straightforward roofs well. The failures concentrate on complex New York City rooftops — HVAC units, skylights, shadows, obstructions, unusual layouts — where equipment gets mistaken for panels, or real panels get missed.

Costly error A

False "solar" → field team visits a roof with no panels.

Costly error B

False "no solar" → real generation potential is missed.

Current state

Ambiguous cases are reviewed by hand — imagery, records, judgment.

Why this slice

We deliberately chose one part of the problem: the low-confidence verification step. Not a new scanner, not streaming imagery — a review layer for the cases the existing system cannot settle.

The approach: a verification layer, not a replacement

  1. Same inputs, several models. Three vision models — Gemini 3.5 Flash-Lite, GPT-5.5, Kimi K3 — classify each roof.
  2. Structured output. label + confidence + reason + difficulty factors + escalate flag (PRD §3 contract).
  3. Fail toward a person. uncertain or low-confidence ⇒ escalate to an analyst. The system recommends; a person decides.

Benchmark

30 rooftop images (19 test + 11 valid) from a CC-licensed public drone dataset. Ground truth locked from 2 labelers; 5 disagreements resolved to uncertain per the labeling rule. Image integrity verified by SHA-256.

Surprising fact from the data

Humans hesitated — models didn't

On the 5 rooftops where our two human labelers disagreed, the models still output confident solar/no_solar calls. Example sv-0133: both humans said no solar, yet Kimi K3 called it solar — a model confident the opposite of a human consensus.

The open-weights model is honest about doubt

Gemma 4 26B marked 11 of 30 roofs uncertain — more than any closed model — yet its escalation recall ties the best. The cheapest model (10× cheaper) is the least over-confident.

Why this matters

A scanner that is confident on exactly the roofs humans hesitate over is the failure mode a verification layer must catch.

One approach that failed — and why

Failed: bare-prompt classification with the default setup

  • What we tried: first pass with Gemini 2.5 Flash models, plain "classify this roof" prompt, default parsing.
  • What failed: 2.5 models returned 404 for new accounts; one model emitted malformed/multi-object JSON; free-tier rate limits (429) stalled ~40 calls.
  • Evidence: result files with error rows; the retry/resume logic in evaluate_benchmark.py; the robust JSON extractor added after the parse failures.
  • Lesson: treat every model output as a candidate, verify the pipeline before trusting any number.

Second failure, worth naming: escalation recall

The scorecard itself caught it — models output confident solar/no_solar on roofs both human labelers called uncertain. A confident wrong answer on an ambiguous roof is exactly what a verification layer must prevent.

One approach that looks promising

Promising: structured three-way contract + human escalation

  • The PRD output contract works: all three models produced parseable label/confidence/reason JSON across 90 calls after the parser fix — the schema is enforceable.
  • Agreement on solar is real: all three models agreed on 13 solar cases and 2/3 agreed broadly — clear cases are separable.
  • The escalation path is the differentiator: a verification layer that routes uncertain/low-confidence cases to a person catches the 43% of roofs where models disagree.
  • Next test: does prompt tuning move escalation recall from 40% toward 1.0 on the 5 ground-truth uncertain cases?

Where this goes

1. Escalation tuning

Re-prompt ("when in doubt, uncertain") and re-score the same 30 images; measure recall.

2. Context signals

Add NYC building footprints + solar-readiness records as optional context (PRD §2).

3. Human-review boundary

Analyst workflow for escalated cases; measure how much manual review is avoided.

What we'd ask Con Edison

  • Which error has historically cost more — false solar or false no-solar?
  • What context data (footprints, permits, historical imagery) is shareable?
  • How should results return to your review tooling?

SolarScan Verify: the scanner stays; the ambiguous roofs get a second, explainable, human-escalated look.
