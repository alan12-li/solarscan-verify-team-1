# SolarScan Verify — Benchmark Dataset v1 Design

Status: Draft
Owner: Yongpeng, Praewa, Kenji, Tanapat, Victor
Linked to: `sims/solarscan-verify/PRD.md` §6 (100-image benchmark)

## Goal

A fixed benchmark of 100 rooftop images with known labels, committed to this
repository before prototype work starts. The benchmark answers one question:
**can a verification layer correctly separate clear cases from ambiguous
ones, and escalate every genuinely ambiguous case?**

## Target label distribution (100 images)

| Label | Count | Why |
|---|---|---|
| `solar` | 35 | Clear panels visible |
| `no_solar` | 35 | No panels; includes HVAC/skylights/obstructions |
| `uncertain` | 30 | Genuinely ambiguous; must be escalated |

The 30 `uncertain` cases are the heart of the benchmark: PRD §6 requires
**escalation recall = 1.0** on them. The 70 clear cases test PRD §6's
**≥90% accuracy** requirement.

## Data sources (all public / licensed / synthetic — no private data)

### 1. Real rooftop imagery — HuggingFace `Francesco/solar-panels-taxvb`

- License: **CC** (verified via HF API)
- **Verified:** 161 images, 640×640 JPEG, DJI drone rooftop imagery with
  COCO annotations (solar-panels / Cell / Cell-Multi / No-Anomaly /
  Shadowing / Unclassified). Splits: train 112 / test 19 / valid 30.
- The `Shadowing` / `Unclassified` annotation classes map directly to PRD
  `difficulty_factors`.
- Used for: the 35 `solar` cases and some `no_solar`/`uncertain` cases where
  imagery shows panels or panel-like structures. If coverage of
  `no_solar`/`uncertain` is insufficient, the remaining cases come from
  synthesis (source 3).

### 2. Context data — NYC Open Data

| Dataset | ID | Fields used |
|---|---|---|
| NYC Building Footprints | `5zhs-2jue` | BIN, BBL, Construction Year, Height Roof, Ground Elevation, Feature Code |
| NYC Municipal Solar-Readiness (Local Law 24) | `cfz5-6fvh` | Site, Address, Borough, Installed/Estimated Capacity, Installation Date |

- License: NYC Open Data policy (public use permitted)
- Used as: the **optional context** the PRD §2 describes — a benchmark case
  can attach building footprint + solar-readiness record as context fields,
  so the prototype is tested with and without context

### 3. Synthetic cases — programmatically generated

- Generated with a small script (`src/` later): rooftops with drawn panels,
  HVAC units, skylights, shadows, obstructions, unusual layouts
- **Full label control** — this is where the 30 `uncertain` cases come from
  (e.g. dark rectangles that could be panels or skylights, half-shadowed
  roofs)
- License: generated by the team, no third-party rights

## Manifest format

One JSON file per benchmark version. Example:

```json
{
  "version": "v1",
  "created": "2026-08-08",
  "image_count": 100,
  "sources": {
    "hf_francesco_solar_panels_taxvb": {"license": "cc", "count": 60},
    "synthetic": {"license": "team-generated", "count": 40}
  },
  "cases": [
    {
      "id": "sv-0001",
      "image": "images/sv-0001.jpg",
      "label": "solar",
      "difficulty_factors": ["none"],
      "context": {
        "building_footprint": "context/building/sv-0001.geojson",
        "solar_readiness": "context/ll24/sv-0001.json"
      },
      "source": "hf_francesco_solar_panels_taxvb",
      "notes": ""
    }
  ]
}
```

## Labeling rules (team agreement)

1. `solar`: panels clearly visible; a reasonable person would agree.
2. `no_solar`: no panels; includes roofs with HVAC/skylights/obstructions.
3. `uncertain`: a reasonable person could not decide from the image alone;
   competing interpretations are plausible.
4. Every case needs **at least two team members** to agree on the label.
   Disagreements become `uncertain` (fail toward escalation, per PRD §5).
5. Labels are recorded in the manifest with the labelers' GitHub handles.
6. Raw media stays out of Git — only the manifest + small previews are
   committed. Full images are regenerated/downloaded by `src/` scripts.

## Directory layout (in team repo)

```
data/benchmark-v1/
├── README.md            # this design doc
├── manifest.json        # the ground truth (committed)
├── images/              # gitignored; downloaded/generated by scripts
├── context/
│   ├── building/        # NYC footprint GeoJSON per case (committed)
│   └── ll24/            # NYC solar-readiness record per case (committed)
└── previews/            # small thumbnails for review (committed)
```

## Acceptance check (what "done" means)

- `manifest.json` has exactly 100 cases with valid labels and image paths.
- Label distribution matches the table above.
- Every case has ≥2 agreeing labelers recorded.
- Every `uncertain` case has a `notes` field explaining the ambiguity.
- A script (`src/validate_benchmark.py`) validates the manifest: image
  existence, label enum, distribution, labeler count.
